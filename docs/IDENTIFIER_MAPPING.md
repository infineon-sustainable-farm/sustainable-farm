## Identifier Strategy Principles

### Core Principle

> Every cross-module relationship must use a stable identifier.

### What Makes an Identifier Stable?

- **Permanent:** Does not change over the lifetime of the entity
- **Unique:** Uniquely identifies the entity across the system
- **Immutable:** Once assigned, never reassigned
- **System-wide:** Recognized by all modules that reference the entity

### Anti-Patterns to Avoid

❌ **Do NOT use display names as integration keys:**
- `"Dryer 1"`
- `"Bloc A"`
- `"Mango Keitt"`

✅ **DO use stable IDs:**
- `machinery_id`
- `bloc_parcelle`
- `variety_id`

## Composite Keys

Some entities require composite keys for system-wide uniqueness:

### Farm + Parcel

```text
Composite key: (farm_id, parcel_id)
Example: (FARM-001, "A")
```

### Farm + Variety

```text
Composite key: (farm_id, variety_id)
Example: (FARM-001, VAR-KEITT)
```

### Batch + Processing Stage

```text
Composite key: (batch_id, processing_stage)
Example: (B-001, "DRYING")
```

## Identifier Format Recommendations

### Suggested Naming Convention

| Type | Format | Example |
|------|--------|---------|
| Farm | `FARM-{sequence}` | `FARM-001` |
| Parcel | `{character}` | `A`, `B`, `C` |
| Variety | `VAR-{name}` | `VAR-KEITT` |
| Harvest | `HV-{year}-{sequence}` | `HV-2026-001` |
| Batch | `B-{year}-{sequence}` | `B-2026-001` |
| Machinery | `EQ-{type}-{sequence}` | `EQ-DRYER-001` |
| Storage | `ST-{location}-{sequence}` | `ST-MAIN-001` |
| Shipment | `SH-{year}-{sequence}` | `SH-2026-001` |
| Order | `ORD-{year}-{sequence}` | `ORD-2026-001` |

## Data Integrity Rules

### 1. Referential Integrity

- All foreign keys must reference valid stable identifiers
- Cascading deletes must be defined for each relationship
- Soft deletes recommended for audit trail preservation

### 2. Identifier Validation

- Validate identifier format before database insertion
- Check uniqueness constraints at application level
- Log identifier conflicts for debugging

### 3. Migration Strategy

- When introducing new identifier schemes, maintain mapping to old identifiers
- Support dual identifier systems during transition periods
- Deprecate old identifiers after confirmed migration
